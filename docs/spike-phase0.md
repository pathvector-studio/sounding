# 段 0 スパイクの結果（2026-11-07）

`specs/phase0.md` の測定結果と決定。スクリプトと数値の出力は `spike/`（`spike/out/` に数値だけ。取得したメールは `spike/data/` に置き、コミットしない）。対象は sidrops の 2026-10-08 以降の 30 日分（146 通）。

## 結論
1. **取得手段は匿名 IMAP（`imap.ietf.org`）を主、rsync の月次 mbox を予備**とする（仮説どおり）。`docs/DESIGN.md` 1.3 を更新した。
2. **スレッド化は自前の JWZ ＋ 件名の補助でサーバーの `THREAD=REFERENCES` と 100% 一致**した。ただし件名の補助は必須（ヘッダーだけでは 69.9%）。
3. **前処理で入力は本文の約 36%、生メールの約 8.5% まで減る**。効いたのは MIME 展開（添付など）と引用の除去で、署名・フッターの寄与は小さい。
4. **LLM の main 段の入力は、sidrops・idr・grow を追っても 1 日 7 万トークン前後（繁忙月で 13 万）** の見込み。入力の 8 割以上は状態 JSON とシステムプロンプトで、メール本文そのものは小さい。
5. スパイクのコードは段 1 で消す。**スレッド化はそのまま段 1 に移し**、**前処理は考え方と規則の形だけ引き継いで書き直す**。

## 取得手段

### 匿名 IMAP
- 匿名ログインは成功（ユーザー `anonymous`、パスワードは `FETCH_CONTACT`）。メールボックス名は `Shared Folders/sidrops`（`LIST` で確認）。
- 所要時間：接続 0.8 秒、ログイン 0.2 秒、`UID THREAD` 0.19 秒、146 通を 6 回に分けて 16 秒。エラーや制限らしき挙動はなかった。
- ログイン後の CAPABILITY に `THREAD=REFERENCES`・`CONDSTORE`・`QRESYNC`・`ESEARCH`・`WITHIN`・`COMPRESS=DEFLATE` がある。**ログイン前には出ない**（spec の「ログイン前に出る」は誤りだった）。
- **`ID` コマンドは非対応**（`BAD Unrecognized command`）。IMAP では、名乗りはパスワードの連絡先だけになる。
- 差分取得は `UIDVALIDITY` ＋ 前回の最大 `UID` で行う（`UIDNEXT` も取れる）。`UIDVALIDITY` が変わったら全件を取り直す。

### rsync の月次 mbox
- 認証なしで取得できる。2026-10 と 2026-11 の 2 ファイルを 2 回取得し、2 回目の転送量は 0 バイトだった。
- IMAP と同じ期間で比べると、**Message-ID は 146/146 一致**。差の 2 通は期間の境界（IMAP の `SINCE` は受信日時で判定）によるもの。From・Subject・References・In-Reply-To・Date は一致し、本文も一致した（1 通だけ mbox の `>From ` エスケープの違い）。アドレスの難読化はない。
- 懸念：差分が月単位で粗い。過去月のファイルも後から書き換わる（2026-06 が 10 月に更新されていた）。将来提供をやめることがある、と IETF のページに注意書きがある。→ 予備にとどめる。

### mailarchive.ietf.org
- 出典リンク（`/arch/msg/<list>/<id>/`）にだけ使う。**Message-ID から恒久 URL を引く方法は未確認**なので、段 1 の spec で確かめる。

## スレッド化
| 方法 | スレッド数 | サーバーとの一致 |
|---|---:|---:|
| サーバーの `THREAD=REFERENCES` | 49 | — |
| JWZ ＋ 件名の補助 | 49 | 146/146（100%） |
| JWZ（ヘッダーだけ） | 56 | 102/146（69.9%） |

- 146 通のうち 38 通は References も In-Reply-To もない。サーバーはこれを件名でまとめている。
- 件名の正規化は、`Re:` と `[sidrops]` を外すだけでは足りない。ゲートウェイが付ける `[Internet]` のような任意の `[...]` タグと、各言語の返信接頭辞（例：中国語の「答复:」）も外す必要があった（RFC 5256 の base subject に合わせた）。
- 最大のスレッドは 36 通、単発は 29 本。

## 前処理の削減率
文字数 ÷ 4 による推定トークン数（正確な数は段 2 でプロバイダの計数を使う）。

| 段階 | 推定トークン | 生メール比 | 本文比 |
|---|---:|---:|---:|
| 1 生のメール（ヘッダー込み） | 461,535 | 100% | |
| 2 本文だけ | 110,360 | 23.9% | 100% |
| 3 引用を除去 | 44,100 | 9.6% | 40.0% |
| 4 署名を除去 | 43,607 | 9.4% | 39.5% |
| 5 フッター・Note Well を除去 | 43,555 | 9.4% | 39.5% |
| 6 自動送信メールを除外 | 39,419 | 8.5% | 35.7% |

- 自動送信メールは 16 通（11%）で、すべて `Auto-Submitted` ヘッダーで判定できた（Datatracker の I-D Action、公開通知、WG 採択の呼びかけなど）。これらは**要約の入力からは外すが、手続きの更新イベントとして残す**べき（WG 採択の呼びかけはダイジェストに出したい）。
- 残ったメッセージの推定トークンは中央値 89、最大 4,056。
- 除去しすぎの確認（20 通を目視）：おおむね問題なし（約 16/20 はきれい）。気になった点：
  - 行間に返信する形式では、引用を全部消すと何に答えたかが分からなくなる。状態 JSON があれば LLM は補えるが、段 1 では**直前の引用を短く残す**ことを検討する。
  - Outlook 形式の引用見出し（`From: … Sent: …`、中国語版を含む）以降を切ると、その下に書かれた返信が消える可能性がある。
  - 議長が手で送る長い議題メールは自動送信扱いにならず、そのまま残る。

## 1 日あたりの入力トークンの見積もり
測定値：sidrops は 1 日平均 4.9 通、前処理後 1,314 トークン、動いたスレッド 2.2 本（30 日中 21 日に動きあり。最大の日は 7 スレッド・9.4k トークン）。ほかのリストは rsync の月次ファイルのサイズ比で概算した（2026 年 1〜10 月、sidrops を 1 として idr 8.28、grow 0.70、ietf 1.31）。

仮定（すべて仮置き）：状態 JSON 1,500 トークン/スレッド、システムプロンプト 1,000 トークン/回、出力 700 トークン/スレッド、ietf は keywords で 15% に絞る、選別の LLM 判定はしない（上限側の見積もり）。

| 想定 | main 入力/日 | main 出力/日 | 費用/日（仮の単価） |
|---|---:|---:|---:|
| sidrops だけ | 6.8k | 1.5k | $0.04 |
| sidrops ＋ idr ＋ grow | 68k | 15k | $0.44 |
| ＋ ietf（keywords で絞る） | 69k | 16k | $0.45 |
| 同上、繁忙月（×1.94） | 134k | 30k | $0.86 |

- 仮の単価は main 入力 $3 / 出力 $15、cheap 入力 $0.25 / 出力 $1.25（100 万トークンあたり）。実際のモデルと単価は段 2 で決める。
- idr のサイズ比は添付や引用を含むので、多めに出ている可能性が高い。
- **入力の大半は状態 JSON とシステムプロンプト**。段 2 では、プロンプトキャッシュ（`docs/DESIGN.md` 5 章の 6）と状態 JSON の短さが費用に最も効く。`LLM_DAILY_BUDGET_USD=1.00` の既定は、この想定では繁忙月でも収まる。

## 段 1 への引き継ぎ
| 部品 | 判定 | 理由と、段 1 でやること |
|---|---|---|
| スレッド化（`spike/thread.py` の `build_threads`・`base_subject`） | **移す** | サーバーと 100% 一致。IMAP や IETF に依存しない純粋な関数で、IETF 固有なのはリストのタグと返信接頭辞の定数だけ（設定に出す）。テストを足す：Message-ID の重複、References のループ、件名が空・極端に短い場合。返すのは今はグループだけなので、木構造が要るならそこも作る。検証は 1 リスト 1 か月だけ |
| 前処理（`spike/preprocess.py`） | **書き直す** | 段階の分け方と、IETF 固有の規則を `RULES` に分けた形は引き継ぐ。関数は 20 通で調整した経験則なので、テスト用のコーパスを作って書き直す。行間返信の引用文脈、各言語の引用見出し、HTML からテキストへの変換を扱う。段階 6 は「除外」ではなくイベントの分類にする |
| 取得（`fetch_imap.py`・`fetch_rsync.sh`） | 書き直す | `SourceAdapter` の形（カーソル＝`UIDVALIDITY` ＋ `UID`）で作り直す。rsync は予備として後回しでよい |

段 1 の spec で確かめること：Message-ID から mailarchive の恒久 URL を引く方法、`UIDVALIDITY` が変わったときの扱い、IMAP の接続が切れたときの再試行、Python 3.12 での実行（このスパイクは標準ライブラリだけで、手元にある新しい Python で動かした）。
